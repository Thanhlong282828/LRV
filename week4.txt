# D22 — Authentication: Register / Login / Logout

## Mục tiêu

Hôm nay trả lời được:

> **“Application biết user hiện tại là ai bằng cách nào?”**

Không cần tự viết authentication system từ số 0.

Được phép dùng authentication package/scaffolding phù hợp với Laravel version đang sử dụng.

Nhưng:

> **Không được chạy installer xong rồi coi như đã học Authentication.**

---

# Phase 1 — Requirement

Application cần:

```text
Guest
├── Register
└── Login

Authenticated User
├── Products
├── Cart
├── Orders
└── Logout
```

---

# Phase 2 — Register

User nhập:

```text
Name
Email
Password
Confirm Password
```

Validation:

```text
Name required
Email required
Email valid
Email unique
Password required
Password confirmation
```

Register thành công:

→ User được lưu database.

→ Password **không được lưu plain text**.

---

# Phase 3 — Login

Correct credentials:

```text
Email + Password
→ Login
```

Wrong credentials:

```text
→ Reject
→ Error message
```

---

# Phase 4 — Protected Page

Tạo:

```text
/profile
```

Guest truy cập:

```text
/profile
```

→ bị yêu cầu login.

Authenticated user:

→ xem được.

---

# Phase 5 — Logout

Logout xong:

→ `/profile` không truy cập được nữa.

---

# Transaction Experiment

Cố tình tạo lỗi sau khi:

> Order đã được tạo

nhưng trước khi:

> OrderItems tạo xong.

Quan sát database.

Nếu Order tồn tại nhưng không có Items:

> Data đã inconsistent.

Sau đó implement transaction.

Test lại.

Expected:

```text
ALL SUCCESS
→ COMMIT

ANY FAILURE
→ ROLLBACK EVERYTHING
```

Đây là cách học transaction tốt hơn thuộc định nghĩa.
