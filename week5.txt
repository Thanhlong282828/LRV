# D29 — REST API Fundamentals

## Mục tiêu

Hiểu sự khác nhau giữa:

```text
Browser → Controller → HTML View
```

và:

```text
Client → API → JSON
```

Không học API bằng cách thuộc:

> REST là Representational State Transfer...

Phải tự build API chạy được.

---

# Phase 1 — API Read

Tạo:

```text
GET /api/products
```

Expected:

```json
{
  "data": [
    {
      "id": 1,
      "name": "Keyboard",
      "price": 350000,
      "stock": 10
    }
  ]
}
```

Không trả HTML.

---

# Phase 2 — Product Detail

```text
GET /api/products/{id}
```

Product tồn tại:

```text
200 OK
```

Không tồn tại:

```text
404
```

Không trả:

```text
200 OK
"Product not found"
```

---

# Phase 3 — Create

```text
POST /api/products
```

Input:

```json
{
  "name": "Keyboard",
  "category_id": 1,
  "price": 350000,
  "stock": 10
}
```

Success:

```text
201 Created
```

---

# Phase 4 — Update

```text
PUT /api/products/{id}
```

Update DB.

Return JSON.

---

# Phase 5 — Delete

```text
DELETE /api/products/{id}
```

Delete đúng Product.

---

---

# Endpoint Matrix

Tạo trước:

`api-permissions.md`

| Endpoint       | Guest | User | Admin |
| -------------- | ----- | ---- | ----- |
| GET Products   | ✓     | ✓    | ✓     |
| GET Product    | ✓     | ✓    | ✓     |
| POST Product   | ✗     | ✗    | ✓     |
| PUT Product    | ✗     | ✗    | ✓     |
| DELETE Product | ✗     | ✗    | ✓     |
| GET My Orders  | ✗     | ✓    | ✓     |
| GET Own Order  | ✗     | ✓    | ✓     |

---

# Authentication

Dùng cơ chế phù hợp với Laravel project hiện tại.

Không cần tự invent JWT implementation.

Mục tiêu hiểu:

```text
Credentials
    ↓
Authentication
    ↓
Token/Session mechanism
    ↓
Authenticated Request
    ↓
Authorization
```

---

# Test Cases

### Guest

```text

```

→ `401`

### Normal User

```text

```

### Admin

→ Success.

### User A

```text

```

→ Reject.

```text

├── Categories
```

- headers;
- body;
- example response.

```text

token
```

Không hard-code token thật vào collection public.
